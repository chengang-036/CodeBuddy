## 双人怎么操作

### 电脑（两个人挤一把键盘）

| | 移动 | 开火 |
|---|---|---|
| **P1（黄）** | `W` `A` `S` `D` | `J` / `F` / `左Shift` |
| **P2（绿）** | `↑` `↓` `←` `→` | `空格` / `K` / `/` |
| 全局 | `P` / `Esc` 暂停，`Enter` 确认，标题页 `←` `→` 换人数 | |

### 手机 / 平板（横屏最佳）

```
       ┌──────────────────────────┐
 P1 黄 │  摇杆      开火     开火  摇杆  │ P2 绿
       └──────────────────────────┘
        左手拇指   左手/右手  右手拇指
```

- **摇杆在外侧，开火键在内侧**：两个人各持手机一端，外侧手推摇杆，内侧手按开火，不会抢同一块屏幕区域。
- 竖屏也能玩（四个控件横排），但 390px 宽度下手指会挤，**建议横屏**。
- 摇杆是浮动原点：手指按在哪里，哪里就是圆心，不用去对准摇杆中心。

## 合作模式规则

| 项 | 规则 |
|---|---|
| 目标 | 共享同一个基地，守住老鹰不被击毁 |
| 生命 | 各 3 条命，**独立结算**；一人打光后出局旁观，队友继续 |
| 失败 | 基地被毁，或两人全部出局 |
| 友军伤害 | **关闭**。玩家子弹不会打到队友（合作模式开友伤只会让两个人吵架） |
| 升级/护盾/加命 | 只作用于**捡到它的那个人** |
| 炸弹/钢化/冻结 | 全场效果，两人共享 |
| 敌人 | 单人 20 辆 / **双人 28 辆**，同屏上限 4 / **6** |
| 敌人 AI | 锁定**最近的那个玩家**——两个人分开走位才能真正分担火力 |

## P0：为什么做「帧同步」而不是「服务器跑逻辑」

坦克大战的状态太小了：13×13 格、6 辆坦克、十几颗子弹。让服务器每帧模拟一遍纯属浪费。

帧同步反过来——**服务器只转发玩家按了什么键，两台手机各自跑同一份逻辑**：

| | 状态同步 | **帧同步（本方案）** |
|---|---|---|
| 上行/下行 | 每帧 1–3KB 快照 | 每帧 1 字节输入 |
| 服务器 | 每局都要跑逻辑，吃 CPU | 只转发，1 核可挂几百房间 |
| 断线重连 | 要传整个场面 | 补发缺失的输入帧即可 |
| 录像/观战 | 要单独录 | 输入历史就是录像 |

代价是**必须保证确定性**：同输入 → 同结果，一比特都不能差。P0 就是在解决这件事，P1 已经把这套内核真正用起来了。

### P0 验证结果

| 丢包率 | 执行帧数 | 逐帧比对 | 等待对方 | 最长卡帧 | 哈希一致 |
|---|---|---|---|---|---|
| 0% | 898 | 898 | 0.2% | 0ms | ✅ |
| 8% | 843 | 843 | 6.3% | 33ms | ✅ |
| 30% | 749 | 748 | 16.8% | 83ms | ✅ |
| 50% | 646 | 645 | 28.3% | 117ms | ✅ |

**结论**：丢包只让推进变慢（等待对方），**不影响正确性**。反例验证：把随机源换回 `Math.random`，第 **39 帧**（0.65 秒）就被检出 desync。

## P1 为 P2 埋的三个伏笔

P1 看起来只是"同屏双人"，但每一处都在给 P2 铺路：

1. **固定步长主循环**（`main.js`）：逻辑固定 60Hz 累加，渲染与逻辑解耦。原来单机版用变 dt，两台手机的 dt 序列永不相同，必分叉。
2. **逻辑层零 `Math.random`**（`rng.js`）：敌人转向、开火冷却、道具掉落、关卡洗牌全部走种子 PRNG。`test-coop.js` 的确定性用例会跑 900 帧比对哈希，漏改一处就会红。
3. **输入即字节**（`input.js`）：每个玩家每帧的状态天然是"上下左右开火"5 个位，P2 接网络时直接打包发送，不用改玩法代码。

## 踩过的坑（都写下来避免重犯）

### P0

1. **输入写指针跳号 → 永久死锁**：追帧后 `pushLocal` 把写指针跳到 `frame + buffer`，中间几帧输入从未写入，两端永久停死。修法：逐帧补齐。
2. **只重发最近 3 帧 → 一帧永久丢失就死锁**：改为按对方 `ack` 批量补发（最多 12 帧/包）。

### P1

3. **出生点被占会导致两车叠死**：`spawnPlayer` 先检查出生点是否被别的坦克占着，占着就返回 false、0.35 秒后重试；只有地形阻挡才清格强生。
4. **P2 的绿色和 4 血装甲兵的绿色几乎一样**：混战里分不清队友和敌人。把装甲兵改成青色系（4 血青 → 3 血黄 → 2 血橙 → 1 血灰白）。
5. **竖屏四个控件横排会叠在一起**：390px 宽要放下"摇杆+开火"各两组，尺寸必须收紧到 `--stick:100 / --fire:66`，且 P1/P2 角标不能外挂在按钮上（外挂会互相压住），改为内嵌。
6. **空格不能无条件当确认键**：双人模式下空格是 P2 开火，只能在菜单/结算页保留"空格=确认"。
7. **桌面端底部提示文案写太长会压住 HI-SCORE 数字**：右侧可用宽度只有约 230px，双人文案必须精简。

## P2 房间码联机（已完成）

两台手机各开一个页面，一个人建房拿到 4 位房号，另一个输房号进来，一起守家。

### 跑起来

```bash
PORT=3000 node server.js          # 生产：托管平台会自动注入 PORT
SERVE_TOOLS=1 PORT=8940 node server.js   # 本地联调（额外开放 tools/ 目录）
```

浏览器打开 `http://<你的地址>/`，标题页点 **在线联机**。

### 结构

| 文件 | 作用 |
|---|---|
| `server.js` | HTTP 静态托管 + `/ws` 升级 + 房间协议 |
| `server/wsframe.js` | 手写 RFC6455（零依赖，不装 `ws`，避免沙箱装包失败） |
| `server/rooms.js` | 房间管理（建房/加入/转发/哈希比对/掉线） |
| `client/js/net.js` | 客户端：连接、房间码、帧同步驱动 |
| `client/js/netinput.js` | 把「网络帧掩码」伪装成 Input 接口，玩法代码零改动 |
| `client/js/statehash.js` | 状态哈希（desync 检测） |
| `client/js/netui.js` | 房间面板（原生 input，手机软键盘才正常） |

服务器**不跑游戏逻辑**：只发房号、转发每帧 1 字节的输入、比对哈希。
所以 1 核小机器能挂上百个房间，录像/观战/断线重连也就顺带都有了。

### 关键机制

- **输入提前量 4 帧**（67ms）：本地按键写到「未来第 4 帧」，抖动在 67ms 内不影响帧率
- **批量补发**：每 tick 从「对端还没执行到的第一帧」补到最新（最多 12 帧）。
  这里踩过两个死锁，见下方「踩坑」第 1、8 条
- **节奏锚在真实时间**：算出「此刻本该执行到第几帧」再追，绝不「能推多少推多少」
- **哈希每 0.5 秒比一次**，含地形与 RNG 取数次数；一有分歧立刻双端报警

### 测试

```bash
node tools/test-net.js       # 服务端 22 项（真进程、真 socket）
node tools/test-online.js    # 双端一致性 21 项（两个独立 vm 上下文）
node tools/test-browser.js   # 真浏览器 E2E 13 项（两个 Chrome 实例 + CDP）
```

`test-browser.js` 是最后一道关：它会真开房、真加入、真按键，
再断言「B 端看到的坦克坐标与 A 端完全一致」。
**它抓到了 Node 测试抓不到的两个 bug**（见踩坑 8、9）。

### 已知限制

1. **微信端还不能用**：`wx.connectSocket` 要求 wss + 已备案域名，并要在小游戏后台配 socket 合法域名。
2. **掉线不能续局**：一方断线整局结束，需要重开房间（本地重连重放还没做）。
3. **没有房间列表/匹配**：只支持房号邀请，故意的——两个人约着玩，不需要大厅。

## 踩坑（P2 新增）

8. **ack 语义多加了 1，永远漏掉第 0 帧**：`peerAck` 存的是「对端还需要的第一帧」，
   补发起点应是 `peerAck` 而不是 `peerAck + 1`。加了 1 之后，后加入的一方从第 1 帧开始发，
   先到的一方永远等不到第 0 帧 → 整局卡死。Node 测试因为两端同时开局（对称）没暴露，
   真浏览器里一端先建房、一端后加入才现形。
9. **测试里两端共用同一个 RNG 单例**：客户端有一批模块级单例（RNG/Sprites/Config），
   同一个 Node 进程里跑两个 Game 实例，随机序列互相污染，测出来的「不一致」全是假的。
   改用 `vm.createContext` 给每个玩家独立 JS 环境，才等价于两台真机。
10. **推进不能「能推多少推多少」**：早期写法直接 `advance(maxCatchUp:10)`，
    一帧内把缓冲里的输入全吃掉，实测 900 tick 推了 4500 帧（5 倍速）。
    必须锚在真实时间上：`expected = startFrame + floor((now - startedAt) / 16.67)`。
11. **后台标签页的 rAF 会被 Chrome 暂停**：E2E 用两个标签页测联机时，后台那个永远不推帧。
    这不是游戏 bug，两个标签页改成两个独立浏览器进程即可（真机本来就是两台设备）。
