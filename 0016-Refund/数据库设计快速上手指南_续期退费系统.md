**给开发人员的核心要点** ⚡

## 📌 核心业务表（必须掌握）

### 1. 退费记录表 (`refund`) - 最核心的表

**关键字段**:
- `id`: 退费ID（格式: `RF` + YYYYMMDD + 3位序号，如 `RF20250507001`）
- `status`: 退费状态（**重点！** 见下方状态枚举）
- `policy_no`: 关联保单号
- `holder_id` / `phone`: 投保人身份证号/手机号（查询用）
- `is_original_card`: 是否原卡原退（影响材料补充流程）
- `material_deadline`: 材料补充截止时间（24小时有效期）

**状态枚举**（`status` 字段）:
```javascript
1: 受理中
2: 受理撤销
3: 审批未完成
4: 审批第一个节点
5: 材料待确认状态    ← 客户需补充材料
6: 材料已确认        ← 材料确认人处理
7: 审批通过          ← 进入退费处理
8: 审批拒绝
9: 退费处理中
10: 退费失败         ← 失败件处理人处理
11: 退费撤销
```

**查询示例**:
```sql
-- 查询某投保人的所有退费记录
SELECT * FROM refund WHERE holder_id = '310101199001011234';

-- 查询待处理退费（材料待确认 + 材料已确认 + 退费失败）
SELECT * FROM refund WHERE status IN (5, 6, 10) AND branch = '上海分公司';
```

---

### 2. 保单表 (`policy`) - 基础数据

**关键字段**:
- `policy_no`: 保单号（主键）
- `holder_id` / `phone`: 投保人身份证号/手机号
- `branch` / `sub_branch`: 分公司/中支
- `sales_channel` / `sub_channel`: 销售渠道/子渠道（**决定审批流！**）

**销售渠道 → 审批渠道映射**:
```
个险渠道 / 个险PAA / 个险PSA → 个险
银保渠道 → 银保
团险渠道 → 团险
在线渠道 → 在线
```

---

### 3. 审批节点表 (`approval_node`) - 审批流核心

**关键字段**:
- `refund_id`: 关联退费ID
- `node_name`: 节点名称（如"分公司业务部门内勤"）
- `node_order`: 节点顺序（1, 2, 3...）
- `status`: 节点状态（`pending` / `completed` / `rejected`）
- `operator_id`: 操作人ID（**重要！** 用于过滤待审批记录）

**查询示例**:
```sql
-- 查询某用户的待审批节点
SELECT an.*, r.status AS refund_status 
FROM approval_node an
JOIN refund r ON an.refund_id = r.id
WHERE an.operator_id = 'U4'  -- 登录用户ID
  AND an.status = 'pending'
  AND r.status IN (3, 4);
```

### 权限检查代码示例（参考）

```javascript
// 检查用户是否有某权限
function hasPermission(userRole, permission) {
  const rolePermMap = {
    'J1': ['Q6', 'Q7'],
    'J2': ['Q1', 'Q2'],
    'J4': ['Q2', 'Q3', 'Q4', 'Q5', 'Q9'],
    // ...
  };
  return rolePermMap[userRole]?.includes(permission) || false;
}

// 使用示例
if (hasPermission(loginState.roleID, 'Q3')) {
  // 显示审批按钮
}
```

## 🔄 审批流配置（重点！）

### 审批流规则

**1. 按销售渠道区分**:
- **个险**: 需要审批（金额 >= 5000 需多级审批）
- **银保/团险**: 需要审批
- **在线**: 5万以下单人审批，5万以上双人审批

**2. 按金额区间区分**（个险/银保/团险）:
- **5000元以下**: 中支层审批（如有中支）或分公司层
- **5000元 - 50万**: 分公司层审批
- **50万及以上**: 总公司层审批（银保/团险除外，仍用分公司层）

**3. 自动审批条件**:
```javascript
// 满足以下条件可自动审批通过
if (amount < 5000 && salesChannel !== '在线') {
  isAutoApproval = true;
}
```

### 审批流配置表 (`approval_flow_config`)

**存储格式**（JSON）:

```json
      ]
```

## 📊 常用查询场景

### 1. 退费受理（95500坐席）
```sql
-- 根据投保人身份证号 + 手机号查询保单
SELECT p.* FROM policy p
WHERE p.holder_id = ? AND p.phone = ?;

-- 创建退费记录
INSERT INTO refund (id, policy_no, holder_name, ...)
VALUES ('RF' + DATE_FORMAT(NOW(), '%Y%m%d') + LPAD(?, 3, '0'), ...);
```

### 2. 审批列表（审批人）
```sql
-- 查询待审批记录（需关联审批节点表）
SELECT r.* FROM refund r
JOIN approval_node an ON r.id = an.refund_id
WHERE an.operator_id = ?  -- 当前登录用户ID
  AND an.status = 'pending'
  AND r.status IN (3, 4)
ORDER BY r.accept_time DESC;
```

### 3. 统计报表
```sql
-- 按状态统计退费数量
SELECT status, status_name, COUNT(*) AS cnt
FROM refund
GROUP BY status, status_name;

-- 按分公司统计退费金额
SELECT branch, SUM(amount) AS total_amount, COUNT(*) AS cnt
FROM refund
WHERE status NOT IN (2, 11)  -- 排除撤销
GROUP BY branch;
```

## ⚠️ 开发注意事项

### 1. 敏感数据加密
**必须加密存储的字段**:
- `policy.holder_id`（身份证号）
- `policy.phone`（手机号）
- `refund.holder_id`（身份证号）
- `refund.phone`（手机号）
- `refund.bank_account`（银行账号）

**建议**: 使用 AES-256 加密，密钥存储在环境变量中

### 2. 数据脱敏显示
**查询时自动脱敏**:
```sql
-- 身份证脱敏
SELECT 
  holder_id,
  CONCAT(LEFT(holder_id, 6), '********', RIGHT(holder_id, 4)) AS holder_id_masked
FROM refund;

-- 手机号脱敏
SELECT 
  phone,
  CONCAT(LEFT(phone, 3), '****', RIGHT(phone, 4)) AS phone_masked
FROM refund;
```

### 3. 事务管理
**必须在同一事务中的操作**:
- 退费状态变更 + 审批节点更新 + 操作日志记录
- 材料确认 + 状态变更 + 短信通知

**示例**:
```sql
START TRANSACTION;

-- 1. 更新退费状态
UPDATE refund SET status = 6, status_name = '材料已确认' WHERE id = ?;

-- 2. 更新审批节点
UPDATE approval_node SET status = 'completed', operator_id = ?, operate_time = NOW() 
WHERE refund_id = ? AND node_order = ?;

-- 3. 插入操作日志
INSERT INTO refund_log (refund_id, time, action, operator, detail)
VALUES (?, NOW(), '材料确认', ?, ?);

COMMIT;
```

### 4. 并发控制
**乐观锁示例**（防止重复审批）:
```sql
-- 更新审批节点时检查状态
UPDATE approval_node 
SET status = 'completed', operator_id = ?
WHERE id = ? 
  AND status = 'pending';  -- 只有待处理状态才能更新

-- 检查受影响行数
-- 如果 affected_rows = 0，说明已被其他人处理
```

## 📞 常见问题解答

### Q1: 如何判断某退费记录是否需要审批？
**A**: 检查 `is_auto_approval` 字段
```javascript
if (refund.is_auto_approval) {
  // 自动审批通过，直接进入材料补充环节
} else {
  // 需要人工审批，进入审批流程
}
```

### Q2: 如何获取某退费记录的当前审批节点？
**A**: 查询 `approval_node` 表
```sql
SELECT * FROM approval_node
WHERE refund_id = ?
  AND status = 'pending'
ORDER BY node_order ASC
LIMIT 1;
```

### Q3: 移动端客户登录后如何查询退费记录？
**A**: 根据 `holder_id` 和 `phone` 查询
```sql
SELECT * FROM refund
WHERE holder_id = ? AND phone = ?
  AND status NOT IN (2, 11)  -- 排除撤销
ORDER BY accept_time DESC;
```

### Q4: 如何配置某分公司/中支的审批节点？
**A**: 修改 `approval_flow_config` 表
```sql
UPDATE approval_flow_config
SET config_value = JSON_SET(config_value, '$.branchTemplates.个险PAA_上海分公司.tiers[0].nodes', JSON_ARRAY(
  JSON_OBJECT('name', '上海分公司业务部门内勤', 'selectedUsers', JSON_ARRAY('U10')),
  JSON_OBJECT('name', '上海分公司业务部门负责人', 'selectedUsers', JSON_ARRAY('U11'))
))
WHERE config_key = 'branch_个险PAA_上海分公司';
```
